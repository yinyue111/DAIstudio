# AI 图片/视频生成平台完整优化实施计划

> 基线日期：2026-07-18
> 范围：完整产品终态，不按一期裁剪。状态只代表当前工作树证据，不代表已上线。

## 1. 目标产品链路

`能力发现 -> 素材输入/解析 -> 图片或视频证据反推 -> 人工审阅校正 -> 选择性应用 -> 目标模型编译 -> 服务端报价 -> 生成 -> 源/生成复刻度评估 -> 修正版本/局部重生成 -> 任务/素材/项目/配方/账务沉淀`

产品组织固定为三层：

- 模型：供应商能力、版本、价格和路由。
- 工作流/配方：用户要完成的创作任务和可重放参数。
- 工具：需要专用交互或多阶段编排的能力。

图片反推、视频反推和提示词优化均在统一 Studio 中完成。目录可提供独立入口，但不得复制独立业务工作台。

## 2. 不可破坏的产品约束

1. 反推结果不得静默覆盖用户当前工作区。
2. 版本血缘必须是 `provider_raw -> normalized -> user_edit -> applied -> model_compiled -> generation`。
3. 切换生成模型只重新编译，不重复视觉反推。
4. “我的提示词”保存文本；Creation Recipe 保存素材、证据、模型版本、参数和完整血缘。
5. 项目和文件夹只关联 `asset_ref`；解除关联或删除项目不得删除真实素材。
6. 客户端价格不具备结算权威性；冻结、结算和退款均绑定服务端 quote/价格版本。
7. 未形成真实证据的 OCR、音频、动作或运镜结论必须标记未知、未支持或降级，不得由文案伪装成已分析。
8. 复刻度评估不得压缩为一个不透明总分；不可用维度必须排除并标记，修正操作只能创建新版本，不能覆盖原反推结果或生成结果。

## 4. 图片反推验收清单

- 每条证据包含稳定 ID、来源图、字段、区域、置信度、事实状态和审阅状态。
- 用户可修改文字和区域、确认/驳回、切换保护/可编辑、拆分/合并/删除。
- 独立 OCR/检测结果与 VLM 冲突时必须展示冲突，不能静默选择其一。
- 只有已确认、可见且区域合法的证据可以生成保护/编辑蒙版。
- 服务端从证据生成或校验最终蒙版；客户端 mask plan 只作为受校验的用户意图。
- 分析报告用途为只读分支，不允许误触发生成。
- 普通反推历史和 Recipe 均能恢复 image evidence；过期素材必须明确提示。

## 5. 视频反推验收清单

- 每个镜头包含绝对时间、片段索引、证据帧、画面、动作、运镜、光线、转场、OCR 和音频引用。
- 多片段证据覆盖率只以已选片段为分母，并正确合并重叠区间。
- OCR 来自逐帧检测并形成跨帧 track；VLM 字幕描述不得冒充 OCR 证据。
- ASR、说话人、BPM/节拍、音乐和音效分别报告状态；未实现或失败时为 unsupported/degraded。
- 时间线支持镜头选择、拆分、合并、排序、锁定和单镜头重分析/生成。
- 批量视频允许每项覆盖片段、关键帧和音频策略。
- 分析报告与模型可执行稿分离；字幕、旁白、音效不混入纯视觉生成提示词。

## 6. 生成后复刻度评估验收清单

- 评估记录同时引用 source `asset_ref`、generated `asset_ref`、反推 operation/revision、生成任务、模型/能力/价格版本快照。
- source 和 generated 均执行 owner gate；generated 必须来自 `GenAsset`，且双方媒体类型一致。
- 图片分别评估构图结构、主体/商品、色彩光线、文字/Logo、细节材质；finding 支持 bbox、严重度、置信度和证据。
- 视频按归一化时间和镜头对齐，分别评估时长节奏、镜头结构、主体动作、运镜、风格、OCR 和音频；finding 支持绝对时间段、镜头和对齐帧。
- 每个分析器独立记录 `succeeded/unsupported/degraded/failed`；不可用维度不进入聚合结果，不以默认满分或文案推断代替证据。
- 用户可选择 findings 生成结构化、提示词、负面提示、蒙版或镜头修正；修正必须创建新的 canonical revision chain。
- 图片允许按选中区域局部重绘，视频允许按选中镜头重生成并重新合成；未选中结果保持不变。
- 本地评估可零费用；任何付费外部评估必须进入服务端 quote、冻结、结算和退款链路。

## 7. 剩余收口顺序

1. 先接入并验收图片检测/分割、视频语义和 ASR/说话人生产分析器，再调整证据可用性门槛。
2. 使用真实供应商完成图片生成/编辑、视频生成、逐镜重生成和 FFmpeg 合成下载。
3. 用真实 MinIO/S3 执行对象迁移、备份恢复和 SHA-256 校验，不以 FakeS3 单测代替。
4. 基于真实事件闭环校验管理端证据采用率、编辑幅度、生成转化、成本和毛利口径。
5. 完成历史库升级、关键迁移降级和生产级恢复演练后，再声明 WP14 完成。
